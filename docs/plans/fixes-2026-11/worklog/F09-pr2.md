# F09 PR 2 — PDB writer worklog

- **Issue:** #67, Fixes F09 - Export to Rekordbox format
- **Branch:** `bradley/rekordbox-export-pdb`

## What changed

- Added `src/library/export/rekordbox/rekordboxpdbwriter.{h,cpp}`:
  - DeviceSQL page layout: 4096-byte pages, header page, table directory,
    index pages, data pages, row index with presence bitmaps, empty candidate
    pages and the file sequence/next-page words.
  - Rows for tracks, genres, artists, albums, keys, colors, playlist tree and
    playlist entries.
  - The eight device colors, the default browse columns, categories and sorts,
    and the `property` row.
  - DeviceSQL string encodings: short ASCII, long ASCII and long UTF-16LE.
- Added `src/test/rekordboxexportpdbtest.cpp`.
- Updated `docs/rekordbox-export.md` with the PDB format and its provenance.
- `CMakeLists.txt`: the new source and test entries.

## Provenance

The owner waived the license gate. The PDB writer is derived from
chrisle/rbxport's `rbl-pdb` at commit
`d0ff75b378ec85be891d9f3067ada1e82bad4cae`; the ANLZ writer is derived from
`rbl-anlz` at the same commit. `LICENSE` and `LICENSING.md` at that commit state
GPL-2.0-or-later, which is compatible with this repository's GPL-2.0-only terms
by choosing version 2. `docs/rekordbox-export.md`, section "Provenance", carries
the verbatim license text and the per-writer statement.

An earlier revision of this worklog framed the rbxport input as an open
decision because the merged F09 plan called it clean-room. The owner has
resolved that: the license gate is waived, the writers are documented as
translations, and no part of this document claims clean-room status.

## Deliberately not covered

- ID allocation and mapping from Paramix tracks, artists, albums, genres and
  playlists. The writer takes numeric ids.
- `labels`, `artwork` and the history tables are empty.
- The full `RekordboxFeature` import path needs a mounted device tree and a
  database connection; the test reads back with the same Kaitai reader instead.
- Audio files, paths on the stick, the export job and the UI.

## Notes for the next PR

- The job must take the media-relative `/Contents/...` path and the
  `/PIONEER/USBANLZ/...` analysis path before building the track rows.
- `property.contents` is set from the track count by the writer; the job sets
  the device name and date.
- Playlists need stable ids; entries reference track ids assigned in the same
  pass.
- Track `colorId` is the 1..8 device color row, not an RGB value.
- The MP3 timing offset remains the job's responsibility, as in the importer.
