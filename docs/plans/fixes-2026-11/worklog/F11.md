# F11 worklog - FX units 1-2 fixed, 3-4 in a window

- **Issue:** #69
- **Branch:** `bradley/fix-fx-banks`
- **Base:** `origin/main` at `2229c27`
- **Status:** implementation complete; PR open, not merged

## What changed

- `res/qml/TopBarEffects.qml` always renders standard units 1 and 2. Paging,
  the page key, the `showAllUnits` four-wide mode and the width-dependent first
  unit are gone. The two units split the full strip width, so their selectors
  get the freed pixels and show longer effect names.
- The super knob now appears per unit: `TopBarEffects.qml` compares each unit
  against its own natural minimum width instead of a strip-wide threshold. At
  the minimum window size both units keep the knob.
- New `res/qml/EffectUnitsWindow.qml` stacks units 3 and 4 using the existing
  `Effects/TopBarEffectUnit.qml`, so there is one unit implementation. It is
  closed by default, resizable, remembers size and position, and clears
  `[Skin],show_4effectunits` when closed from the title bar.
- `res/qml/MainWindow.qml`: one `FX 3-4` checkable toolbar key and one View menu
  item, both bound to `[Skin],show_4effectunits`. The window is instantiated
  from the toolbar key, matching the Pad FX pattern.
- `res/qml/Effects/TopBarEffectUnit.qml`: tooltips and a pointing cursor on the
  A-D deck assign keys, tooltips on the slot On keys, and in-window positioning
  for the parameter flyout. It flips above the unit when the parameter columns
  would fall past the bottom edge and clamps both edges to the window, so the
  flyout stays usable in the small effects window. (Qt 6.4 has no
  `Popup.popupType`, so a native popup window is not an option on the minimum
  supported Qt.)
- `res/qml/Effects/EffectAssignmentButtons.qml`: removed the stale
  `[Skin],show_4effectunits` proxy and the two/four-unit branch. The four
  assignment keys are always present, sized from Theme tokens.
- `res/qml/Theme/Theme.qml`: removed the now-unused `fxSuperMinWidth` token.
- `docs/paramix-ui-design-system.md`: effects row now describes the fixed
  strip, the per-unit super knob and the units 3-4 window.

## Decisions

- **Geometry persistence stays QML-only.** The QML UI has no settings object,
  and `Qt.labs.settings` is not in this static Qt build's QML import scanner
  (adding it would need a CMake reconfigure and relink). The window therefore
  creates four persisted `[Skin]` controls through `Mixxx.SkinControlCreator`:
  `effectunits_window_x`, `effectunits_window_y`,
  `effectunits_window_width`, `effectunits_window_height`. This mirrors the
  deck pane persistence already in `Deck.qml`. Defaults (`-1` for position, `0`
  for size) mark "never stored".
- **Close is handled in `onClosing`, not `onVisibleChanged`.** Quitting the app
  with the window open must keep the persisted open state; only a user-initiated
  close clears the control.
- **Flyouts stay inside the window.** The first PR revision used
  `Popup.popupType: Popup.Window` to let the parameter columns and effect list
  extend past the effects window. `Popup.popupType` does not exist in Qt 6.4,
  the minimum supported Qt, so CI failed to load `TopBarEffectUnit.qml`. The
  property is gone; the parameter flyout now flips above the unit and clamps to
  the window edges instead. The flyout is still bounded by the window height; a
  flyout that must extend outside the window would be a separate change and
  needs a minimum-Qt bump.
- The strip height and `Theme.topBarEffectsHeight` are unchanged, so the bounds
  test expectations did not need updating.
