> **Prior lane attempt.** `docs/plans/fixes-2026-11/worklog/F01-stem-flicker.md`
> (commit `cd1d95b` on this branch) records an earlier re-test that also could not use a
> display, concluded that the existing early-out already covered the frame path, and
> left the renderer unchanged. That analysis is correct about a *bit-identical* input:
> the `GeometryKey` early-out does skip the rebuild. What it does not cover is the input

## Was #55 already covering part of this?

Yes, partly.

- #55 (`671f9f7`) retains the last stem picture while a detail rebuild is running and
  keeps the previous geometry when a refresh publishes zero lanes, and it skips stale
  negative visual positions on a paused deck. That removed the "picture blinks out"
  class of the report.
- The 2026-11-18 performance pass on `main` (the pause cadence in `QmlWaveformDisplay`
  and the cache's "no queued build per frame while one is pending" guard) removed the
  per-frame build scheduling that could have looked like flicker.
- What remained was the placement path itself: the picture was still positioned from a
  fractional sample offset every pass, derived its column width from the rounded
  viewport, and asked the cache on every frame.

Because there was no display, "does it still reproduce" could not be answered. Instead
of guessing, the pass was hardened so that the stated invariant holds by construction,
and a test now pins it.

## The invariant

For a deck with a zero visual play rate and a fixed zoom and size:

1. consecutive preprocess passes produce the same first detail column,
2. the same texture range (origin and width),
3. the same texture column offset — a whole number of texels,
4. the same detail cache key,
5. and no new cache request or texture rebuild.

## What changed (renderer code did change)

`src/waveform/renderers/allshader/waveformrendererstem.{h,cpp}`

1. **Paused position snaps to whole detail columns.** The renderer reads the deck
   `play` control (new `ControlProxy`, null for group-less displays such as the static
   library preview, which are treated as stationary). With the play button off, the
   first displayed sample is rounded onto the `samplesPerColumn` grid. With no
   sub-column offset, the nearest-filtered texture samples exactly one texel per
   device pixel, so a fractional visual position cannot alternate texels between
   frames.
2. **Texture origin is column aligned while paused.** A texture retained from a
   playing pass can have an arbitrary origin; a fractional texel offset recreates the
   same shimmer. When the deck pauses and the retained origin is not on the grid, the
   texture is rebuilt once on the grid. This is a single rebuild on the pause
   transition, not a per-frame one. The retained-range behavior from #55 is unchanged.
3. **`samplesPerColumn` comes from the zoom, not the viewport.**
   `stemdetail::samplesPerColumn()` uses `getAudioSamplePerPixel()` and the device
   pixel ratio (`2 * audioSamplesPerPixel / dpr`), which is exactly what the previous
   viewport-derived formula computed up to the rounding of `length * devicePixelRatio`.
   Resizing or re-measuring the widget can no longer change the value that is part of
   the detail cache key.
4. **The cache is not asked again for an unchanged key.** `stemdetail::DetailRequestMemo`
   remembers the last `StemDetailKey` (track, sample rate, samples per column, lane
   height, magnification). `request()` — and its mutex and LRU move — only runs when
   the key changes or `detailReady()` reports a completed rebuild. A null answer is not
   memoized, so the first build is still polled.
5. Track id and sample rate are now read in the existing once-a-second metadata refresh
   instead of `pTrack->getId()` on every frame.

The geometry early-out (`GeometryKey`, #55) is unchanged and now compares the snapped
first sample, the retained texture range and the same inputs as before.

### Testable helpers

The pure part of the layout lives in `namespace allshader::stemdetail` in
`waveformrendererstem.h`, so the invariant can be exercised without a scene graph or a
display: `samplesPerColumn`, `snapToColumn`, `isColumnAligned`, `columnIndex`,
`TextureRange`, `textureRangeCovers`, `textureRangeFor`, `DetailRequestMemo`.

## Tests

`src/test/stemdetailrenderertest.cpp`:

- `StemDetailColumns.FollowsZoomAndNotTheRoundedViewport` — the column width is the same
  for every viewport width and agrees with the old viewport derivation within its
  rounding.
- `StemDetailPausedFrame.ConsecutivePreprocessPassesAreIdentical` — eight passes at a
  fixed position with a deliberate sub-column wobble produce the same column start,
  texture range and whole-texel UV offset, and rebuild the texture only on the first
  pass.
- `StemDetailPausedFrame.WholeTrackTextureIsStableWhileScrolling` — the fixed
  whole-track texture keeps its origin across positions near both ends of the track.
- `StemDetailRequestMemo.UnchangedKeyDoesNotAskTheCacheAgain` — an unchanged key never
  requests again; a completed rebuild and a zoom/height change do.

Results: `./build/mixxx-test --gtest_filter='StemDetail*'` — see the PR. `tools/paramix_verify.sh` — see the PR.

## Follow-ups / unverified

- **Visual confirmation is still required:** a paused stem track at min, default and
  max zoom, on both decks, with and without a separation job running. The cause was
  never observed, so "the flicker is gone" is an inference from the invariant, not a
  sighting.
- **Frame timing while playing** was not measured (the plan asks for a 30 s QSG
  comparison). The change removes work from the paused path (no cache mutex per frame)
  and adds nothing to the playing path except one `ControlProxy::toBool()`.
- `res/qml/WaveformDisplay.qml` was not touched, per the lane rules.
- The 30 fps paused cap (`kPausedUpdateIntervalMs`) was not changed; with a stable
  picture the repaint itself is now a no-op in the scene graph.
