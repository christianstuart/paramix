## What the mock specified

- Perform-first pad card (default): 72 px lit pad face, effect name, an `H` / `L`
  / `1×` mode badge with tooltip, four labelled stem chips in stem colors and
  All / Instrumental / Vocals shortcuts, all at least 24 px high.
- `padN_active` lights the pad; `padN_muted` draws an amber `⊘ MUTING` marker,
  independent of the active bit, so a finished one-shot still shows it.
- A per-pad pencil disclosure; one pad expands in place, siblings collapse to
  26 px summaries. Only the expanded pad shows the effect/mode selectors and the
  effect's labelled sliders. Exit with `Done`, another pad's pencil, or Escape.
- A-D bank keys per deck bound to `bank`, with the forced reset to bank 1 gone.
- Deck count from `MainWindow.show4decks`, two wide columns for two decks, and
  two-up paging when four decks do not fit.
- Empty state with state-specific copy and a `Separate stems` key calling
  `Mixxx.StemService.generateStems(track)`.
- Tooltips and `Accessible.name` on every control; sizes from Theme tokens; five
  new Pad FX tokens.

## What was implemented

### `res/qml/Theme/Theme.qml` (additive block after the FX strip tokens)

`padfxPadHeight` (`space8 + space2` = 72), `padfxHitHeight`
(`max(24, fontSizeXs + 2*space2)` = 25), `padfxControlHeight` (26 at scale 1),
`padfxModeBadgeHeight` (`space4` = 16), `padfxDeckMinWidth` (300 at scale 1).
No component hard-codes a pixel size any more.

### `res/qml/PadFxDeckPanel.qml` (rewritten)

- Keeping `padFxGroup`, `stem_count`, the A-D bank keys, the four pad cards and
  the seven Per-Pad controls. Adds `padN_muted`.
- **Perform view**: the pad face is the LED. Fill switches between `surface3`
  and `Theme.accent`; text switches to `textOnAccent`; an `Off` pad is dimmed to
  55 %. Caption `PAD N`, effect name `fontSizeMd`/DemiBold, mode pill top-right,
  amber `⊘ MUTING` pill bottom-right from `padN_muted`, pencil rail on the right
  edge outside the pad button.
- **Chips and shortcuts**: four chips with a stem-color dot and label (Drums,
  Bass, Other, Vocals), stem-color border and 18 % fill when on. Clicking still
  goes through `toggleTarget()`, so the last bit can never be cleared. Preset
  keys write 15, 7 or 8 and light only on an exact mask match.
- **Edit view** (`editingPad` local state): expanded header with the mode pill
  and `Done`, effect and mode `Skin.ComboBox` rows with 64 px labels, the same
  chips/shortcuts, then only the labelled `PadFxParameter` rows for the selected
  effect. Siblings are one-line summaries (`PAD 2 · Echo Out · 1× · Vocals`)
  with their own pencil key and muting marker. Escape exits through a
  per-panel `Shortcut` that is only enabled while that panel is editing.
- **Empty state**: one panel replaces the grid while `stem_count == 0`. Copy
  follows the mock's table (no track, service unavailable, no model, queued,
  separating with `StemService.progress`, ready-but-not-loaded, no stems, failed
  with `messageForTrack`). `Separate stems` is shown only when the service and
  model exist and the track has no usable stems; it calls
  `Mixxx.StemService.generateStems(currentTrack)`. Status is re-read from
  `statusForTrack`/`messageForTrack` on load, track change, `queueChanged`,
  `stemsReady` and `trackStatusChanged`.
- The pad face row, chip row and shortcut row are shared between perform and
  edit, so retargeting works while editing.

### `res/qml/PadFxParameter.qml`

Row height and label width now come from Theme. Adds `ownerLabel`, a tooltip,
and `Accessible.name` / `Accessible.description` / `Accessible.role: Slider`.
The inner `Skin.Slider` is sized to the row instead of its own fixed 30 px.

### `res/qml/PadFxWindow.qml`

- New `deckCount` property (passed by MainWindow) and a local `page` property.
- `columnsPerPage` = 2 for two decks; 4 for four decks when
  `width >= 4 * padfxDeckMinWidth + 5 * space2` (1240 at scale 1), otherwise 2.
  A `Decks 1-2` / `Decks 3-4` key appears only when paging; changing width or
  deck count clamps the page. Paging only changes which panels exist; it never
  writes a control, so a pad left running on the hidden page keeps running.
- Header now carries the page key and a Close key, both with tooltips and
  `Accessible.name`.

### `res/qml/MainWindow.qml` (owned lines only)

- `Skin.PadFxWindow { deckCount: root.show4decks ? 4 : 2 }`.
- Tooltip added to the existing Pad FX toolbar key. The View menu item already
  toggles the same window and was left as it was.

### `docs/pad-fx.md`

Software-controls section rewritten for perform/edit, banks, paging, the empty
state, the muting marker and accessibility. `padN_muted` added to the control
listing, and the stale "one bank per deck / unused bank configurations are not
loaded" limitation replaced with the real bank-switch behaviour.

## Deviations / judgement calls

- **Slider rows are 26 px as specified, but `Skin.Slider` keeps its 14 px handle
  lifted 5 px above the row**; no clipping occurs because layouts do not clip,
  but a reviewer should eyeball the overlap with the row above.
- The mock's header drawing shows a static "Decks 1-2 of 4" counter. I show the
  paging key only when paging is active, to keep the header clean at four-up
  width and at two decks.
- The mock's `padfxPadHeight` and chip width are fixed at the default scale;
  the card does not stretch the pad face when a taller window gives the column
  more height, so extra height collects at the bottom of each card.
- At very large font scales the four-up threshold still follows
  `padfxDeckMinWidth` (which only tracks `uiScale`), not the rendered chip text.
  Paging therefore does not happen "earlier with a large font" as the mock
  describes. Chips elide instead.
- Escape uses a `Shortcut` on the deck panel, enabled only while that deck is
  editing. This relies on the Pad FX window having keyboard focus.
