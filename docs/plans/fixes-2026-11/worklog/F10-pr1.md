# F10 PR 1 - Controller-based MIDI mapping backend

- **Issue:** #68 (Fixes F10 - Controller-based MIDI mapping UI)
- **Branch:** `bradley/midi-mapping-backend`
- **Worktree:** `/Users/christianstuart/Documents/paramix-wt/mapping`
- **Scope:** backend only. The QML window and the click-to-learn overlay are PR 2.

## What changed

### 1. Control inventory as a list model

`src/controllers/controlpickermenu.{h,cpp}`

- New `ControlPickerEntry` (group, key, title, description, category, category path).
- New `ControlPickerModel` (`QAbstractListModel`) with the roles `group`, `key`,
  `configKey`, `title`, `description`, `category`, `categoryPath`, plus
  `count()`, `get(row)` and `rowForConfigKey(group, key)`.
- `ControlPickerMenu` appends to the model while it builds its submenus, so the
  classic wizard's inventory, order, titles and descriptions are unchanged.
  The category is derived from the menu ancestry, not from a separate list.
- `ControlPickerModel::createDetached()` builds the inventory without the caller
  owning or showing a QMenu. The control definitions still live in
  `ControlPickerMenu`'s constructor; the detached instance is created and
  discarded internally, and the returned model has no QMenu API. Splitting the
  definitions from the widget itself would have meant rewriting the 2,000-line
  constructor and risking the wizard, so that is left for a later cleanup.

`ControlPickerMenu::controlModel()` exposes the model for the classic
preferences dialog if it ever wants to use it.

### 2. `Mixxx.ControllerLearning`

New `src/qml/qmlcontrollerlearningproxy.{h,cpp}`.

QML singleton `ControllerLearning`, main thread only, no QtWidgets API:

| API | Notes |
|---|---|
| `start(device)` / C++ `start(Controller*)` | MIDI only. Creates a mapping if the device has none, then puts the controller into learning mode. |
| `stop()` | Leaves learning mode. Learned mappings and the session list survive, so they can still be saved. |
| `learning`, `deviceName` | State and device name. |
| `lastMessage` | `status`, `control`, `value`, `channel`, `opCode`, `opCodeName`, `type` (`button`/`knob`/`relative`/`fourteenBit`/`other`), `message`, and `existingMapping` when the message is already mapped. |
| `suggestedMappings`, `suggestedMappingCount` | `LearningUtils::guessMidiInputMappings` over the current 1.5 s gesture: status/control/channel/opCode, option bit mask and translated option names, detected type. |
| `finishDetection()` | Forces detection for the collected messages; the detection timer calls it automatically. |
| `existingMappingFor(message)` | Looks up a message in the working mapping. Accepts `lastMessage` or any map with `status` + `control`. |
| `assign(group, key, options)` / `assignConfigKey("group,key", options)` | Assigns the suggested message(s) to a control. Optional overrides: `switch`, `button`, `invert`, `softTakeover`, `selectKnob`, `spread64`, `fourteenBit`, raw `options`. |
| `remove(group, key)` / `removeConfigKey(...)` / `removeAt(row)` / `clearPendingMappings()` | Delete learned controls ("undo"). |
| `pendingMappings` | `QAbstractListModel` of the controls learned in this session with the physical message summary and option names. |
| `availableControls` | Lazily created `ControlPickerModel` for the searchable list (PR 2). |
| `save(name)` | Writes the user mapping and returns its path. Bundled mappings are copied to a new user file and never modified. |
| `mappingName`, `mappingFilePath`, `lastError` | Display state. |

Reuse: `MidiController::messageReceived`, `Controller::startLearning` /
`stopLearning` (invoked through the meta-object because they are protected
slots), `LearningUtils::guessMidiInputMappings`, `LegacyMidiControllerMapping`
and `LegacyControllerMappingFileHandler` through `saveMapping`.

Threading follows the classic wizard: the proxy edits the controller's mutable
mapping copy on the GUI thread, pushes assignments to the controller thread
with the same temporary-mapping slots the wizard uses, and removes mappings
through a functor queued to the controller thread. `startLearning` /
`stopLearning` are invoked with `Qt::AutoConnection` (direct in tests, queued in
the application) and never touch controller state from the GUI thread.

`save()` writes the file and then adopts it through
`ControllerManager::slotApplyMapping` with a blocking queued connection, the
same protocol `DlgPrefController` uses. That records the mapping path in the
configuration so the mapping loads at the next start. Without a registered
manager (unit tests) it adopts directly on the single thread.

`src/qml/qmlpreferencesproxy.{h,cpp}` got one additive member:
`QmlControllerManagerProxy::registeredManager()`. It exposes the manager that
`CoreServices` already registers so the learning proxy can reach the controller
thread without duplicating the singleton. No `Mixxx.ControllerManager` type was
duplicated or changed otherwise.

### 3. Tests

New `src/test/qmlcontrollerlearningproxytest.cpp` with a fake MIDI controller
that injects short messages:

- `ControlPickerModelTest`: inventory is available without a menu, roles and
  `get()` match, and the classic menu and model stay in sync.
- Button: Note On 0x7F / Note Off 0x00 produces two mappings, detects `button`,
  drives a `ControlPushButton`, and appears once in `pendingMappings`.
- Knob: a 7-bit CC sweep detects an absolute knob, then the same physical
  control is reassigned to another control and only one mapping remains.
- Relative encoder: a two's complement ticker detects `SelectKnob`, accepts an
  `invert` override, and `existingMappingFor()` returns the assigned control.
- Save: a button plus a relative encoder are saved to the user mapping
  directory and reloaded with `LegacyControllerMappingFileHandler`; the file is
  not dirty afterwards.
- `stop()` keeps the learned mapping and the session list.

## Known limits / follow-ups for PR 2

- The detection buffer uses the same 1.5 s gesture timeout as the wizard and is
  capped at 256 messages so a jog wheel that never pauses stays cheap. A very
  slow knob turn can still be split into two gestures; PR 2 can expose the
  timeout if that shows up in practice.
- `save()` uses the mapping name for the file name. Overwrite prompts and
  rename UI live in PR 2 / classic preferences; the backend only never writes
  into the bundled mapping directory.
- The detached-inventory compromise above: no QMenu is exposed to consumers,
  but building the inventory still constructs a detached menu internally.
- Click-to-learn in QML, the window, the toolbar entry and the searchable list
  are PR 2.
