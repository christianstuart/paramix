# F04 - Remove the `--new-ui` launch flag: worklog

- **Issue:** #62
- **Branch:** `bradley/fix-remove-new-ui-flag`
- **Lane / wave:** Shell, wave 1

## What changed

The `--new-ui` option, the hidden `--qml` alias, `CmdlineArgs::m_qml`,
`CmdlineArgs::isQml()`, `--allow-dangerous-data-corruption-risk`,
`m_awareOfRisk` and `isAwareOfRisk()` are gone. It was already a no-op for the
UI choice; the only remaining behavior it gated was the Mixxx 3.0
data-corruption check.

- `src/qml/qmlapplication.cpp`: deleted the Mixxx 3.0 data-corruption gate.
  Paramix uses the same schema as the classic UI, so the gate had no purpose.
  The rest of the constructor still reports startup failures by returning and
  setting `m_loadSucceeded` rather than calling `exit()`.
- `src/util/restartapplication.{h,cpp}`: no longer filters or appends the old
  flags, and the `useQml` boolean is gone. The function has no caller after the
  Help-menu action and the QML proxy method were removed; it stays in place
  because `CMakeLists.txt` still lists the source file. Deleting it needs a
  CMake edit, which is outside this lane.
- `src/widget/wmainmenubar.cpp`: removed the Help menu **Use Paramix QML
  Interface** restart action.
- `src/qml/qmlapplicationproxy.{h,cpp}`: removed the `restartApplication(bool)`
  `Q_INVOKABLE`. Nothing in `res/qml` called it; it only existed to switch UI.
- `packaging/android/AndroidManifest.xml`: dropped `--new-ui` from the launch
  arguments.
- `src/test/qml/qmlstartupsmoketest.cpp`: the `NewUi` parameter is now
  `useDefaultQml` / `DefaultQml`. The test name is the only change.
- `AGENTS.md`, `docs/paramix-ui-design-system.md`,
  `docs/controller-mapping-compatibility-plan.md`: describe the flag as removed
  and the QML interface as the only one.

### Compatibility shim

`CmdlineArgs` still registers a hidden `new-ui` option and warns:

```text
The argument '--new-ui' is no longer needed; Paramix always loads the QML
interface. Ignoring it.
```

This keeps an old shortcut or desktop file working instead of failing on an
unknown option. Remove the shim in the release after this one.

## Call-site resolution

Every `isQml()` call site was resolved to the behavior a normal launch already
had (flag absent). Nothing was flipped.

| File | Current (flag-absent) behavior kept |
|---|---|
| `src/library/librarycontrol.cpp` | All `[Library]` / `[Playlist]` navigation controls stay connected. |
| `src/library/scanner/libraryscanner.cpp` | Scanner progress dialog signals stay connected. |
| `src/preferences/dialog/dlgprefinterface.cpp` | Paramix Interface group stays hidden; classic skin options stay visible; multi-sampling stays disabled and hidden. |
| `src/preferences/dialog/dlgprefmixer.cpp` | Four-band EQ checkbox stays hidden; no Paramix-settings notification on apply. |
| `src/skin/legacy/legacyskinparser.cpp` | Overview, visual, spinny and VU meter widgets are still parsed. |
| `src/preferences/upgrade.cpp` | A new profile gets `VersionStore::version()`, not `3.0-unstable`. |

## Follow-up decisions (not changed here)

1. `DlgPrefInterface` now never populates or applies the `[Paramix]` appearance
   settings, and the Interface/Mixer Paramix groups stay hidden. A QML-only app
   probably wants those controls visible again. Showing them is a behavior
   change, so it is left for a follow-up.
2. `DlgPrefMixer::slotApply()` no longer calls
   `QmlConfigProxyBase::notifyParamixSettings()` because that call was inside
   the removed `isQml()` branch. If the Paramix settings group is re-enabled,
   the notification should come back.
3. `restartApplication()` is now callerless (see above). Delete the utility and
   its `CMakeLists.txt` entry in a follow-up.
4. `res/translations/*.ts` still contain the removed option and dialog source
   strings. They are generated files owned by the localization workflow.
